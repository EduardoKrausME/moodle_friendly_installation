App per portal

Each domain can keep its own visual identity and Android package, while APK and AAB generation runs through the queue and leaves a clear processing history.

How it works

The app area keeps configuration tied to the domain. The administrator opens the desired environment, defines the visual identity, saves the Package UID and uploads the icon.

The build does not happen inside the web request. It is registered as a job and processed by the same runner responsible for privileged tasks, allowing the result to be followed without keeping the browser blocked during the entire build.

Each portal can keep its own name, package and identity without mixing one institution artifacts with another.

The app follows the domain: identity, package and artifacts remain separated per portal.
